## What the plugin builds

One run creates or replaces only its own three pages and updates its own two
variable collections by name; everything else in the file is left alone.

| Page | Contents |
|---|---|
| `Foundations` | 143 variables shown as swatches, primitive ramps, the type ramp, the state legend (glyph, hex, contrast), motion and geometry notes |
| `Components` | 11 component sets + 4 single components (82 variants), listed below |
| `Screens` | Overview 1440×900, Run detail, Needs attention, Overview 390 wide, Unavailable, Empty |

The plugin refuses to run unless `figma.root.name` contains `Fleetglint`, has
no network access in its manifest, and closes with a summary line.

## How to run (and re-run)

1. Open the file above in Figma desktop.
2. **Plugins → Development → Import plugin from manifest…** →
   `design/figma-plugin/manifest.json` (re-import after the 2026-11-05
   manifest change; Figma caches the manifest).
3. **Plugins → Development → Fleetglint Design System**.
4. The summary appears in a toast: pages, collections, styles, variants,
   screens, and any font fallback or warning. The same run always leaves a
   `fleetglint-build-log` text node at the top-left of `Foundations` with the
   timestamp, result, step, error and warnings.

Re-running is safe: it clears its own three pages, updates
`Primitives` / `Semantic` by name, and rebuilds the rest from the token object
at the top of `code.js`.

## Components

Variants are Figma component-set properties; text is overridden per instance
in the screens.

| Component | Variants | Notes |
|---|---|---|
| `StateBadge` | `state` (12) × `size` sm/md × `age` none/suffix = 48 | every display state in brief §3; the age suffix is sample text `42m`, overridden per instance |
| `StateTransition` | — | `running → stale 42m`, writer state → display state |
| `SourceChip` | `status` ok / discontinuity / unavailable / quarantine | status dot + `source_id` |
| `EvidenceLabel` | `kind` process / refresh / none | `pid ok 12s`, `refresh 3m`, `no evidence` |
| `RefLink` | `kind` record / external / unresolved | unresolved adds a dashed underline and `not seen` |
| `RunRow` | `density` compact/default × `interaction` rest/hover/selected = 6 | badge, title, model, role, project, age, evidence/waits-on |
| `JobRow` | `density` compact/default = 2 | command in mono, kind, owning run, exit |
| `InboxItem` | `tone` action / normal / acked = 3 | action tone gets the attention surface and border |
| `CountTile` | `key` running / waiting / attention / stale-lost-unknown = 4 | number + label + state badge |
| `TopBar` | `source` ok / discontinuity / unavailable = 3 | mark, source chips, refresh, read-only |
| `Banner` | `kind` unavailable / discontinuity / quarantine = 3 | board-level source problems |

## Tokens

- `Primitives`: color ramps (neutral, accent, green, amber, red, violet, grey,
  warm, orange, blue), spacing 2–48 on a 4 px base, radius 0/2/4/8, font sizes
  12/13/16/20/28, motion 120/200/1600 ms, row heights 28/32.
- `Semantic` (mode `dark` only): 7 surfaces, 6 text roles, 5 line roles, 12
  state families (fg/bg/border), 4 provenance roles. Every value aliases a
  primitive.
- Text styles: Inter for UI (row 13, meta 12, badge 12, headings 16/20) and
  JetBrains Mono for data (13/12/12, number 28). Missing fonts fall back and
  the plugin says so.

## Screens

Realistic data from `examples/v1/valid/lead-worker-job.ndjson` (the lead →
worker → job → inbox chain), plus a few runs across three projects and four
agents/models, one `stale`, one `lost`, one `unknown`, and a source with a
discontinuity. The screens are read-only: no buttons that change a workflow.

- **Overview** — count tiles, runs grouped by project, waiting rows show what
  they wait on, terminal runs collapsed and quiet; source health in the top
  bar. Also at 390 wide.
- **Run detail** — header with `StateTransition` and evidence, relationships,
  owned jobs, version history, usage with its basis label, log tail, raw
  redacted fields.
- **Needs attention** — action-required inbox items first, then open items,
  then `lost`, then `stale`/`unknown`, then source problems.
- **Unavailable** and **Empty** — board-wide states, no sample data shown as
  current.

## Deviations from the brief

1. **No node ids or screenshots in this phase.** The plugin was written and
   checked as code; it has not run in Figma here. The table above and the
   screenshots are filled in after the Owner runs it.
2. **Running pulse is static.** Figma's plugin API cannot animate canvas
   nodes, so the pulse is specified as the `motion/ambient` 1600 ms token and
   the badge uses a filled dot plus ring. Reduced motion is documented, not
   executable in a static file.
3. **Hatched background only behind the glyph** for `unknown`, because the
   badge itself is an auto-layout component; a full-badge hatch would need a
   fixed-size background and break text sizing.
4. **The 390-wide overview uses a compact row** assembled from `StateBadge`
   plus text, not the fixed-column `RunRow`; the desktop row's columns do not
   fit 390 px. All other rows are `RunRow` instances.
5. **Inbox encodings are three states** (`attention`, `inbox-open`,
   `inbox-acked`) in the same `StateBadge` set; brief §3 lists them as rows of
   the same table, and one set keeps them consistent.
6. **Age suffix is a variant**, not a free text field: `age=suffix` shows
   `42m` as sample text, overridden per instance. Figma component properties
   would add a second mechanism for the same thing.
7. **Sample data is illustrative**, not real records: ids such as
   `eps-runner-19` do not exist in the example file.
